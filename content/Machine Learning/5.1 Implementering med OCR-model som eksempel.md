Hvis vi sammenligner PyTorch-implementeringerne med ONNX-implementeringerne, kan man se hvor relativt meget mere komplekst det var at implementere ONNX-versionerne. Nedenstående kode viser implementeringen af PyTorch-versionen af PaddleOCR-modellen:

```python
from paddleocr import TextRecognition

recognition = TextRecognition(
    model_name="en_PP-OCRv5_mobile_rec",
    device="cpu"
)

def read_licenseplate(plate_crop):
    out = recognition.predict(plate_crop, batch_size=1)
    if not out:
        return None, None
    text = out[0]["recognition_text"]
    score = out[0]["recognition_score"]
    return text, score
```

Her instantieres recognition til at være modellen, der ligger på computeren, og sættes til at køre på CPU fremfor GPU (fordi det var ligegyldigt for os hvor effektivt det kørte under tests, og der er mindre bøvl med CPU).

`read_licenseplate`-metoden tager et NumPy-array, som repræsenterer et billede af en nummerplade, som parameter. `batch_size=1` fordi vi læser ét billede ad gangen, hvis den kan genkende noget på billedet som tegn, returnerer modellen, hvad den har læst, og hvor sikker den er på, at det er korrekt - dens confidence score. Færdigt arbejde. 

Tager vi i stedet et kig på ONNX-implementeringen, er det en anden sag. Lad os løbende sammenligne implementeringen.

For lige kort at reiterere: PyTorch-versionen bruger paddleocr-biblioteket, vi har installeret. Derfor 'får' den version en masse ting gratis - f.eks. ved den automatisk hvilken ordbog den skal bruge, når den læser tegn. ONNX-modellen er derimod en rå, matematisk model, og vi skal derfor selv stå for at lime de forskellige dele sammen, for at modellen rent faktisk kan bruges til noget. Så hvis vi igen tager ordbogen som eksempel, måtte vi ind og lede i det officielle repo for at finde den ordbog, der passede til modellen og servere den for ONNX-modellen:

### Initialisering

##### PyTorch
```python
recognition = TextRecognition(
    model_name="en_PP-OCRv5_mobile_rec",
    device="cpu"
)
```

##### ONNX
```python
# 1. Load dictionary
with open("ppocrv5_dict.txt", "r", encoding="utf-8") as f:
    char_list = [""] + [line.strip() for line in f]

# 2. Load ONNX model
session = ort.InferenceSession("models/en_ppocrv5_mobile_rec_clean.onnx")
```

Vi starter med at indlæse ordbogen (+ en 'tom' character i index 0) i et array, så vi kan oversætte modellens output til noget meningsfuldt. Derefter indlæser vi modellen. ONNX-runtimen bestemmer om vi bruger CPU eller GPU.

### Preprocessing
##### PyTorch
```python
out = rec.predict(plate_crop, batch_size=1)
```

Her håndteres resizing, normalisering og transponering af det importerede bibliotek. Dette skal håndteres manuelt ved ONNX:

##### ONNX
```python
# 1. Resize til modellens forventede inputdimensioner
img = cv2.resize(plate_crop, (320, 48))

# 2. Normaliser (0-255 -> 0.0-1.0)
img = img.astype(np.float32) / 255.0

# 3. Transponer til modellens forventede matrix-format HWC -> CHW
img = np.transpose(img, (2, 0, 1))

# 4. Tilføj batch-dimension (NCHW)
input_tensor = np.expand_dims(img, axis=0)
```

Først justeres størrelsen (1); derefter normaliseres billedets pixel-RGB-værdier til at være mellem 0 og 1 (2); så transponeres HWC-formatet (Height, Width, Channel) til CHW; og til sidst tilføjes en ekstra batch-dimension, fordi modellen kan arbejde med billed-batches. Så selvom vi kun arbejder med et enkelt billede ad gangen, skal denne dimension tilføjes. Alt det her kan virke lidt trivielt og som logik for viderekomne, men det er nødvendigt for at få modellen til at køre.

### Inferens og post-processing

##### PyTorch
```python
def read_licenseplate(plate_crop):
    out = recognition.predict(plate_crop, batch_size=1)
    if not out:
        return None, None
    text = out[0]["recognition_text"]
    score = out[0]["recognition_score"]
    return text, score
```

Selve kørslen af modellen er ikke mere kompliceret med ONNX, men de to versioner differentierer i output. Hvor PyTorch-modellen pænt outputter det ønskede resultat, klar til at blive læst, outputter ONNX-modellen en rå sandsynlighedsmatrix:
##### ONNX
```python
input_name = session.get_inputs()[0].name
output_name = session.get_outputs()[0].name

output = session.run([output_name], {input_name: input_tensor})[0]
```

Igen må vi bøje os for ONNX-logikken: De første to linjer henter dynamisk interne navne. Dette gør koden robust, så den ikke crasher, hvis eksport-processen tilfældigvis har navngivet inputtet `x` i stedet for `input_tensor`.

Selve `session.run` er inferensen. Her mapper vi vores tensor til input-navnet og fortæller eksplicit (via listen `[output_name]`), hvilken del af grafen vi vil have beregnet – en optimering der sparer hukommelse, hvis modellen havde haft flere ubrugte outputs.

Ved at indlæse ONNX-modellen på https://netron.app/ kan man få visualiseret grafen. Nedenstående screenshot viser slutningen af grafen - de enkelte noder er ikke så afgørende her, det interessante er, at den slutter med et enkelt output. Ved at inspicere modellen visuelt, kan vi således udlede, at det nødvendigvis er `outputs()[0]` , vi er interesseret i. Fordi der kun er et enkelt output, kunne vi således også køre koden med 
```python
results = session.run(None, {input_name: input_tensor})
```
da det fortæller modellen bare at beregne alle outputs i grafen. I dette tilfælde ville det ikke gøre nogen forskel.

Nu har vi så vores output - *sandsynlighedsmatricen*. PyTorch-modellen giver os noget der kunne minde om en json-menu, vi kan bestille text og score fra:
##### PyTorch
```python
    text = out[0]["recognition_text"]
    score = out[0]["recognition_score"]
```

ONNX-versionen er knapt så hjælpsom og giver os blot ingredienserne - matricen - så må vi selv stå for tilberedningen - post-processing:
##### ONNX
```python
probs = np.squeeze(output, 0)
preds = np.argmax(probs, axis=-1)

prev = -1
chars, confs = [], []
for t, idx in enumerate(preds):
    if idx != prev and idx != 0:
        chars.append(char_list[idx])
        confs.append(probs[t, idx])
    prev = idx

text  = "".join(chars)
score = float(np.median(confs)) if confs else 0.0
return apply_plate_rules(text), score
```

Den første linje:
```python
probs = np.squeeze(output, 0)
```
bruger en NumPy-metode til at barbere den ekstra batch-dimension af - fordi vi kun har ét billede, er den dimension overflødig. Det giver os 2D sandsynlighedsmatricen, som på den ene akse består af *time steps* - som er vertikale udsnit af billedet. Fordi modellen tager billeder af 320 pixels bredde og laver udsnit på 8 pixels, forsøger den således at læse karakterer fra hvert udsnit - 40 i alt. På den anden akse har vi tegnene fra vores ordbog. Selvom vi kun skal læse danske nummerplader (A-Z, 0-9), er denne specifikke model præ-trænet på et bredere datasæt, der inkluderer matematiske symboler, valuta og accenter. Derfor består output-matricen af ca. 440 kolonner, selvom vi egentlig kun interesserer os for de kolonner, der repræsenterer tegn der kan optræde på nummerplader. Modellen tillægger en sandsynlighed til hver karakter, hvilket giver en komplet matrice som visualiseret nedenfor:

Anden linje:

```python
preds = np.argmax(probs, axis=-1)
```

udnytter en NumPy-metode til at finde indekset på den karakter, der har højest sandsynlighed for hvert time step. Det giver os således en række tal, hvor hvert tal svarer til et tegn i vores ordbog.

```python
prev = -1
chars, confs = [], []
for t, idx in enumerate(preds):
    if idx != prev and idx != 0:
        chars.append(char_list[idx])
        confs.append(probs[t, idx])
    prev = idx
```

Her går vi igennem vores array af indekser, og hvis et indeks **ikke** er det samme som det forrige, bliver den tilsvarende karakter taget med i vores endelige char-array. Fordi et tegn kan strække sig over flere timesteps (f.eks. vil et 'A' der er 24 pixels bredt måske optræde 3 gange i træk), er det nødvendigt at 'rengøre' aflæsningen. Tilfælde som 'AA' bliver også håndteret, hvor modellen indsætter en 'blank' token imellem de to identiske tegn for at adskille dem. For hvert tegn vi tilføjer går vi tilbage i sandsynlighedsmatricen og finder dets tilhørende confidence-score. På den måde får vi den komplette læsning af tegnene på billedet og de tilhørende sandsynligheder. 

```python
text  = "".join(chars)
score = float(np.median(confs)) if confs else 0.0
return apply_plate_rules(text), score
```

Den endelige confidence score bliver median-scoren, for at finde en score der både er balanceret men som ikke bliver påvirket af evt. outliers. I første omgang havde vi faktisk besluttet at tage minimums-sikkerheden, men en enkelt outlier kunne således diskvalificere hele læsningen, hvilket ikke var hensigtsmæssigt. Ligeledes ville en gennemsnitsværdi blive påvirket kraftigt af outliers, og vi endte derfor med at gå med medianen. Nu er vi så endelig nået til samme punkt som PyTorch-versionen automatisk spyttede ud.

Til sidst kan jeg lige vise vores forsøg på at optimere læsningen af nummerpladen med nogle regler - dette er dog ren post-processing og ville altså skulle bruges på samme måde med begge modeller:

```python
def apply_plate_rules(raw):
    cleaned = raw.replace(" ", "").upper()
    trimmed = cleaned[-7:]

    if len(trimmed) < 7:
        return trimmed

    letters = list(trimmed[:2])
    digits  = list(trimmed[2:])

    letter_fix = {
        "0": "O", "1": "I", "2": "Z", "3": "E", "4": "A",
        "5": "S", "6": "G", "7": "T", "8": "B", "9": "P",
    }

    digit_fix = {
        "O": "0", "Q": "0",
        "I": "1", "L": "1", "|": "1",
        "Z": "2",
        "E": "3",
        "A": "4",
        "S": "5",
        "G": "6",
        "T": "7",
        "B": "8",
        "P": "9",
    }

    letters = [letter_fix.get(c, c) for c in letters]
    digits  = [digit_fix.get(c, c) for c in digits]

    corrected = "".join(letters + digits)

    return corrected if re.fullmatch(r"[A-Z]{2}\d{5}", corrected) else cleaned
```

Vi starter med at fjerne evt. mellemrum. Derefter trimmer vi læsningen til de sidste 7 læste tegn fordi danske nummerplader er 7 tegn - 2 bogstaver og 5 tal. Vi tager de sidste 7 fremfor de første 7, fordi modellen nogle gange læser landekoden i starten med, hvilket vi på denne måde undgår. Vi gemmer dog den oprindelige som fallback, hvis vi ikke kan komme frem til en nummerplade, der ligner en normal dansk plade. Hvis modellen er kommet frem til en nummerpladelæsning på mindre end 7 tegn, returnerer vi med det samme, da den åbenlyst ikke passer med en normal plade. Hvis ikke, retter vi evt. bogstaver, der optræder hvor vi forventer tal, til tal der ligner bogstavet, hvis der er et match i vores hjemmelavede oversætter - og omvendt med tal hvor der burde være bogstaver. Hvis vi således ender med en nummerplade, der passer med en normal dansk plade, returneres den - hvis ikke returnerer vi den oprindelige læsning af pladen i stedet for den redigerede version, da vores forsøg på at matche med det typiske danske format ikke lykkedes.

Dette udgør således hele vores OCR-pipeline. De to andre modeller er objektdetektionsmodeller og virker således væsentligt anderledes, men jeg vil nøjes med ovenstående kodeeksempel som billede på hvordan vi har arbejdet med modellerne i Python og ONNX.
